# 嵌入式内核的 C 高级用法

用最原生（标准 C + GNU 扩展）的语法讲这些技巧，去掉工程别名宏。

## 1. `container_of`：从"内嵌成员"反推"外层对象"

内核常把控制块内嵌的链表结点挂在各种链表里，链表里拿到的是"成员的地址"，要取回外层对象，用 `container_of`：

```c
#define container_of(ptr, type, member) \
    ({ \
        typeof(((type*)0)->member)* __mptr = (ptr); \
        (type*)((char*)__mptr - offsetof(type, member)); \
    })
```

- `offsetof(type, member)`：编译期算出成员在结构体内的偏移。
- 成员地址 − 偏移 = 结构体首地址，就是外层对象。
- `({ ... })` 是 **GNU statement expression**：整个块的值 = 最后一行，可当普通值用。
- `typeof(((type*)0)->member)* __mptr = (ptr)` 顺带做**类型检查**。

用法：遍历链表拿到 `wait_node`，再反推是哪个线程。这就是"结构体即继承、成员即子对象"的 C 式 OOP。

## 2. 就绪表位图 + `__builtin_ctz` 找最高优先级

就绪表维护一个从低位到高位标记的位图，每个优先级一 bit。挑最高优先级 = 找**最低的置 1 位**，用 `__builtin_ctz`（count trailing zeros，一条指令）：

```c
static unsigned highest_ready(unsigned ready_map)
{
    if (ready_map == 0u)
        return MAX_PRIORITY;        // 没有就绪
    return (unsigned)__builtin_ctz(ready_map);   // 返回最低置位位的位置
}
```

比线性扫 `0..N` 快得多，调度器关键路径常用。

## 3. `__attribute__((constructor))`：链接期自动初始化

让函数在 `main` 前自动执行，用来做各种模块的注册/初始化，免手工 `xxx_init()` 序列：

```c
__attribute__((constructor))
void timer_module_init(void) { /* 无需在 main 里显式调用 */ }

// 还能定义优先级:
void __attribute__((constructor(200))) early();   // 数值小的先执行
```

## 4. `__attribute__((weak))`：弱符号，应用按需覆盖默认实现

内核提供默认的空闲钩子，应用可用**强符号**覆盖同名弱实现，不改内核源码：

```c
__attribute__((weak))
int on_idle(void) { /* 默认空转 */ }

// 应用里：int on_idle(void){ __my_idle_code(); }  // 强覆盖弱
```

链接时符号冲突**强覆盖弱**，于是应用定义同名函数即可替换默认行为。

## 5. `__attribute__((naked))`：裸函数，现场完全由汇编控制

```c
__attribute__((naked))
void svc_handler(void) { /* 汇编: 保存现场. 编译器不插序言/尾声 */ }
```

没有编译器帮忙压栈进栈，全部寄存器保存由手写汇编负责——适合上下文切换。

## 6. `_Static_assert` + volatile 寄存器访问

用 `_Static_assert` 把配置约束写死在编译期：

```c
_Static_assert((WHEEL_SIZE & (WHEEL_SIZE - 1)) == 0,
               "tick wheel 必须 2 的幂");
```

寄存器直操作（SysTick 等）用 volatile 指针：

```c
#define SYSTICK_CTRL        (*(volatile uint32_t*)0xE000E010)
#define SYSTICK_RELOAD      (*(volatile uint32_t*)0xE000E014)
```

## 7. `_Generic`（C11）：编译期按类型选函数

C11 的 `_Generic` 相当于"编译期类型分发"，常用来为不同类型的原子/算术选函数：

```c
#define atomic_xchg(p, v) \
    _Generic((p), \
        int32_t*:     xchg_i32, \
        uint32_t*:    xchg_u32)(p, v)
```

编译器选对的那个函数，另一个分支不生成代码。

## 8. 互斥锁优先级继承：沿等待链传播优先级

**问题**：低优先级线程持锁，高优先级线程等待，会无限卡死。
**解法**：沿"等待者 → 持有者 → 该持有者等待的锁"链条，把高优先级一路冒泡传上去，让持锁的低优先线程临时提升优先级、尽快放锁。

实现要点：每个线程维护一个"已持有锁"链表（`hold_list`），锁和线程互相挂接，删锁/解锁时倒序遍历传播并还原。

## 9. 线程控制块：一个结构体内嵌多个链表结点

```c
struct thread {
    list_node   ready_node;   // 挂就绪链表
    list_node   wait_node;    // 挂等待(同步对象)链表
    list_node   hold_list;    // 已持有的锁链表
    /* ... */
};
```

- 同一对象能同时挂在多个不同链表 = 一种对象多角色，靠 `container_of` 取回线程。
- 栈初始化时手写异常返回帧（Cortex-M 入栈顺序），是移植层精细活。

## 小结

| 技巧 | 一句话 |
| --- | --- |
| `container_of` + statement expression | 成员反推外层对象 + 类型检查 |
| 位图 + `__builtin_ctz` | 一条指令找最高优先级 |
| `__attribute__((constructor))` | 链接期自动初始化 |
| `weak` | 弱符号可被强覆盖 |
| `naked` | 裸函数，现场全由汇编控制 |
| `_Static_assert` / `volatile 寄存器宏` | 编译期约束 + 直接访问硬件 |
| `_Generic` | 编译期按类型分派 |
| 优先级继承 | 防低优先级持锁饿死高优先级 |
| 结构体多链表结点 | 一对象多角色 + container_of |
