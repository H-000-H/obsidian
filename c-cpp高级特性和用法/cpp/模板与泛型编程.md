# 🧬 C++ 模板与泛型编程教学手册

> [!INFO] 笔记概览
> - **核心命题**：模板把"类型/常量"当作编译期参数，**一份代码适配多种类型**，且对每种用到的类型各生成一份、运行期零额外开销。
> - **内容范围**：函数模板 · 类模板 · 非类型模板参数（NTTP）· CRTP 静态多态 · 模板特化 · `if constexpr` 编译期分支 · 完美转发与万能引用
> - **推荐路径**：§1 函数模板 → §2 类模板 → §3 NTTP → §4 CRTP → §5 特化 → §6 `if constexpr` → §7 完美转发 → §8 小结

## 🎯 1. 为什么需要模板：一份代码，类型随便换

想写"比较两个数谁大"，要支持 `int`、`float`、`double`。不写模板就得每种类型复制一份：

```cpp
bool max_int(int a, int b)         { return a > b; }
bool max_float(float a, float b)   { return a > b; }
bool max_double(double a, double b){ return a > b; }
```

用模板，把类型当作"参数"：

```cpp
template <typename T>
inline bool greater_than(const T& a, const T& b)
{
    return a > b;
}

bool r1 = greater_than(3, 5);        // T 自动推断为 int
bool r2 = greater_than(1.5, 2.5);    // T 自动推断为 double
```

> [!NOTE] 编译期展开
> `typename T` 是类型占位符；编译期对用到的每种 `T` 各生成一份代码（实例化），运行期零额外开销。没用到的 `T` 不会生成。

## 📦 2. 类模板：一个骨架，多套数据

```cpp
#include <string>

template <typename T>
class Box
{
public:
    void put(const T& v) { m_val = v; }
    T    get() const     { return m_val; }
private:
    T m_val{};                       // {} 值初始化，避免未初始化 UB
};

Box<int>         ib;                 // 只能放 int
Box<std::string> sb;                 // 只能放 std::string
```

> [!CAUTION] 实例之间互不兼容
> `Box<int>` 和 `Box<std::string>` 是两套**完全无关**的类型，互相不能赋值、不能比较。类模板名本身不是类型，加上模板实参才是。

## 🔢 3. 非类型模板参数（NTTP）：常量也能当模板参数

除了类型，还能传整数/枚举，编译期就确定：

```cpp
template <typename T, int N>
class Array
{
public:
    int size() const { return N; }
private:
    T m_data[N]{};                   // N 编译期已知，可用来定数组大小
};

Array<int, 8>  a8;
Array<int, 16> a16;
```

> [!TIP] NTTP 的价值
> `N` 在编译期已知，所以能拿来定数组大小、做 `static_assert(N > 0)`、参与常量折叠。这正是 ETL 定容容器（`etl::vector<T, N>`）的基础，见 [[ETL容器与萃取]]。

## 🪞 4. CRTP：基类模板参数传"子类自己"

普通继承时基类不知道子类是谁；让基类名字里带子类，它就能在编译期"调用子类刚补全的东西"：

```cpp
template <typename Derived>
class Counter
{
public:
    int add(int x)
    {
        // 把 this 转回真正的子类来调（编译期已知类型，无需 virtual）
        return static_cast<Derived*>(this)->step(x);
    }
};

class Doubling : public Counter<Doubling>   // 子类把自己传给模板参数
{
public:
    int step(int x) { return x * 2; }       // 无 virtual，无虚表开销
};
```

> [!NOTE] 静态多态
> CRTP（Curiously Recurring Template Pattern）用**编译期静态分派**替代虚函数的运行期动态分派：省掉 vtable、调用可直接内联，高性能/嵌入式场景常用；不同子类实例互不干扰。与 `enum`/模板多态的对比见 [[枚举constexpr多态与GCC扩展]]。

## 🍳 5. 模板特化：给特定类型"开小灶"

```cpp
#include <string>

template <typename T>
std::string describe()
{
    return "generic";
}

template <>                            // 全特化：针对 std::string 单独写
std::string describe<std::string>()
{
    return "a string!";
}

describe<int>();          // "generic"
describe<std::string>();  // "a string!"
```

> [!TIP] 先通用后特殊
> 先写通用版，再为特殊类型覆盖。可配合 `static_assert` 当作"支持清单"，在编译期拒绝未特化的类型。

## 🔀 6. `if constexpr`：编译期分支，不编译的另一边根本不存在

```cpp
#include <iostream>
#include <type_traits>

template <typename T>
void check(T value)
{
    if constexpr (std::is_pointer_v<T>)   // 编译期就知道真假
    {
        std::cout << "它是指针\n";
    }
    else
    {
        std::cout << "它不是指针\n";
    }
}
```

> [!CAUTION] 与普通 if 的本质区别
> 普通 `if` 两边都会编译（只是运行期选一边）；`if constexpr` 在编译期只保留成立的一边，**另一边根本不被实例化**。因此可以写"对指针才合法、对值类型会编译失败"的代码而不报错，适合处理同一函数的几种互斥组合。

## 🏓 7. 完美转发 + 万能引用：参数原样接力

`T&&` 在模板里是**万能引用**（左值右值都能接），配合 `std::forward` 保持原值类别传下去：

```cpp
#include <utility>

template <typename T>
void relay(T&& v)                       // 万能引用（转发引用）
{
    use(std::forward<T>(v));            // 保持 v 原本是左值还是右值
}
```

> [!WARNING] 易错点
> 直接写 `v`（会退化成左值）或 `std::move(v)`（无条件当右值）都会**丢失调用方本来的值类别**。只有 `std::forward<T>(v)` 能"原样接力"。移动语义滥用易出内存问题，水平不足时优先用 `const T&`。

## 📊 8. 小结

| 特性 | 一句话 |
| :--- | :--- |
| 函数模板 | 类型当参数，写一次 |
| 类模板 | 一个骨架，多套数据 |
| 非类型模板参数（NTTP） | 常量也能当模板参数 |
| CRTP | 子类传给自己，无虚开销的静态多态 |
| 模板特化 | 给个别类型开小灶 |
| `if constexpr` | 编译期选分支，另一侧不编译 |
| 完美转发 | 原样接力左值/右值 |

## ✅ 落地校验清单（Checklist）

> [!SUCCESS] 写模板代码前逐条核对
> - [ ] **能用非模板就别用模板**：模板增加编译时间与符号膨胀，仅在确需泛型时使用
> - [ ] **`{}` 初始化**：成员用 `T m_val{};` 值初始化，杜绝未初始化 UB
> - [ ] **`const T&` 传参**：接口优先常量引用，避免无意义拷贝
> - [ ] **NTTP 约束**：用 `static_assert` 校验编译期常量（如 `N > 0`）
> - [ ] **CRTP 转型**：`static_cast<Derived*>(this)` 而非 `dynamic_cast`（禁 RTTI）
> - [ ] **`if constexpr`**：互斥类型分支用它，避免无效实例化编译错误
> - [ ] **完美转发**：转发用 `std::forward<T>`，不要误用 `std::move`
> - [ ] **克制元编程**：避免过度模板元编程（TMP），保持可审查的简单子集
