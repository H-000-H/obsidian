# 🛑 STOP 调度类原理（停机调度）

> [!INFO] 笔记概览
> - **定位**：STOP 是 Linux **优先级最高**的调度类，但它不是给普通任务用的"调度策略"，而是内核为了**在 CPU 上执行"绝不允许被打断"的代码**而准备的一套内部机制。本篇讲它为什么存在、语义是什么、如何用；源码落地见 [[linux/stop|Linux STOP 实现与注意]]。
> - **内容范围**：为什么需要"停机" · 独占语义（不可抢占/不可迁移/不可让出） · 单核停机 vs 多核停机 · 典型用途 · 与其他调度类的关系 · 代价与风险
> - **推荐路径**：§1 为什么需要 → §2 语义 → §3 单核与多核 → §4 用途 → §5 定位与代价

---

## ❓ 1. 为什么需要"停机"

有些内核操作要求**在它执行期间，本 CPU（甚至所有 CPU）上不能有任何其他代码在跑**，例如：

- 改写内核代码段（`text_poke` / ftrace / kprobes 打补丁）；
- CPU 热插拔的关键阶段；
- 修改全局硬件寄存器（如 MTRR）；
- 需要"所有 CPU 同时到达某个点"的同步。

普通手段（关中断、`preempt_disable`）只能挡住**本 CPU 上的部分**干扰，挡不住**其他 CPU**，也挡不住调度器把当前任务换下去。于是内核需要一种"**把 CPU 冻结、只跑我这段代码**"的能力。

STOP 调度类就是承载这件事的载体：**一个每 CPU 一个的、优先级压过一切的停机任务**。

> [!NOTE] 它不是"给用户的任务"
> 用户态**没有** `SCHED_STOP`。STOP 任务是内核自己创建的内核线程，只在需要时被唤醒干活，干完立刻又回去"停着"。

---

## 🔒 2. 独占语义

STOP 类的核心特征就一条：**一旦它被选中运行，就没人能把它换下去**。具体表现为：

| 维度 | 行为 | 原因 |
|---|---|---|
| 抢占 | **不可被抢占** | 它是最高的类，没有更高的类能压它 |
| 让出 | **不可 yield** | 让出 CPU 就违背了"独占"的目的 |
| 迁移 | **不可迁移** | 停机是"针对某个 CPU"的操作，换核就没意义了 |
| 优先级 | 不可更改 | 它是特殊实体，不是普通任务 |

> [!WARNING] 停机 ≠ 关中断
> 关中断只屏蔽**中断**，不屏蔽**本 CPU 上的其他任务/内核线程**（比如另一个 softirq、另一个内核线程）。STOP 是**在调度层面**把 CPU 让给它独占，粒度比关中断更大。两者常配合使用，但不是一回事。

## 🔧 3. 单核停机与多核停机

### 3.1 单核停机

**目标**：让**某一个** CPU 停下来，执行一段函数。

- 往目标 CPU 的停机任务上**投递一个工作项**（函数 + 参数）；
- 该 CPU 的停机任务被唤醒 → 抢占一切 → 执行函数 → 报告结果；
- 发起方**等待完成**后继续。

适合"只需要在某一个 CPU 上做点事"的场景（如该 CPU 的 hotplug 收尾）。

### 3.2 多核停机

**目标**：让**一组 CPU（或全部）同时**停下来，执行一段函数。

这里有个关键难点：**所有 CPU 必须同时进入"停机"状态**，否则先停的 CPU 会一直等后停的，而后者可能正被前者需要的锁卡住 → 死锁。

为此引入一个**多核同步状态机**，所有参与者按阶段同步推进：

```
PREPARE → RUN → (可选) DISABLE_IRQ → ENABLE_IRQ → EXIT
```

- 每个 CPU 到达一个阶段就登记，等**全部到齐**才进入下一阶段；
- 真正的业务函数**只在 RUN 阶段执行**；
- 通常会临时**禁用中断**，保证"停机窗口"内不被打扰。

> [!NOTE] "最后一个人"语义
> 多核停机里的 `stop_machine` 常见做法是：每个 CPU 都跑到同一个函数里，但**只有最后一个到达的 CPU 真正执行目标逻辑**（或每个 CPU 执行各自的回调）。这保证了"所有人都在场"这个前提。

## 🧰 4. 典型用途

| 用途 | 为什么必须停机 |
|---|---|
| **CPU 热插拔** | 下线 CPU 前要确保它不再执行任何任务、不再持有锁 |
| **内核代码打补丁** | 改写正在被其他 CPU 执行的指令，必须先让它们停住 |
| **ftrace / kprobes** | 同上，动态修改指令流 |
| **MTRR / 硬件全局配置** | 需要独占 CPU 保证寄存器写入的原子性 |
| **同步点** | 需要"所有 CPU 同时到达"的强同步语义 |

> 归纳：凡是**"改了会影响所有 CPU 的全局状态"**或**"改了正在被执行的代码"**，都需要停机。

---

## 📐 5. 调度类层级中的位置

Linux 的调度类按优先级从高到低**固定**排列（见 [[linux/cfs|Linux CFS/EEVDF 实现与注意]]）：

```
stop  >  dl  >  rt  >  fair  >  ext  >  idle
```

- STOP 排在**最前**，所以任何 CPU 只要停机任务就绪，就一定会选它；
- 这也是为什么"停机"能真正做到"独占"——不是靠关抢占，而是靠**类优先级天然最高**。

> [!TIP] 为什么不让 STOP 也用"抢占"实现？
> 因为抢占只能压住**低优先级**的东西，压不住"同类/更高类"。只有把它放在层级**最顶端**，才能保证对**所有**其他调度类都有效。

## ⚠️ 6. 代价与风险

> [!WARNING] 停机是"全局停顿"，代价很大
> - **延迟尖峰**：停机期间该 CPU 完全不响应任何任务，实时性敏感场景会看到明显抖动；
> - **可能死锁**：若被停 CPU 正持有别人需要的锁，而发起方又持有别人需要的锁，就会卡死；因此停机代码里**绝不能睡眠、不能拿可能被其他 CPU 持有的锁**；
> - **不能滥用**：它是"最后手段"，能用更轻量同步（RCU、IPI、per-CPU 变量）解决的，不要用停机。

**设计准则**：

1. 停机函数必须**短小**、**不可睡眠**、**不依赖会被他人持有的锁**；
2. 能单核停机就不要多核停机；
3. 能不用停机就不用——它是正确性工具，不是性能工具。

---

## 🧭 一句话总结

> **STOP 是内核的"最高优先级停机任务"：把某个（或某组）CPU 完全冻结，只跑一段不允许被打断的代码，用完立刻放行。它服务的是内核正确性（改代码段、热插拔），而不是普通任务的调度需求。**
