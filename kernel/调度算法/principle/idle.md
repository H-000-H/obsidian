# 💤 IDLE 调度类原理（空闲调度）

> [!INFO] 笔记概览
> - **定位**：IDLE 是 Linux **优先级最低**的调度类，承载"每个 CPU 都有的那个空闲任务"。它的职责不是"调度谁跑"，而是**当没有活干时，把 CPU 安全地送进低功耗状态，并保证一有活就能立刻醒来**。源码落地见 [[linux/idle|Linux IDLE 实现与注意]]。
> - **内容范围**：空闲任务与 idle 循环 · 与 `SCHED_IDLE` 策略的关键区别 · cpuidle 与 C-state · 无滴答（tickless / NOHZ） · 轮询 vs 深睡 · 空闲负载均衡 · 常见误区
> - **推荐路径**：§1 空闲任务 → §2 与 SCHED_IDLE 的区别 → §3 idle 循环 → §4 省电与唤醒 → §5 边界与误区

---

## 🛌 1. 空闲任务：每 CPU 一个，永远就绪

### 1.1 它是什么

内核为**每个 CPU** 静态创建一个**空闲任务**（idle task / swapper）：

- 它是该 CPU 的 **PID 0**，也叫 `swapper/N`；
- 它是**内核线程**，没有用户态地址空间；
- 它**永远处于可运行状态**（"总是 ready"），因此 `cfs`/`rt` 等队列为空时，调度器总能选到它，绝不会"选不出任务"。

### 1.2 为什么"永远就绪"很重要

调度器的基本假设是：**只要 CPU 在线，就一定有东西可跑**。空闲任务就是那个兜底的东西。

- 没有它，CPU 在无事可做时会出现"无任务可调度"的空白状态，需要额外分支处理；
- 有了它，调度逻辑可以统一为"总能在就绪结构里找到下一个"，而"省电"这件事被封装进空闲任务自己的代码里。

> [!NOTE] 空闲任务是"最低优先级"的体现
> 它属于 **IDLE 调度类**，优先级低于 fair（普通进程）——只要有**任何**普通任务可运行，空闲任务就选不上。

## ⚠️ 2. 关键区别：IDLE 调度类 ≠ `SCHED_IDLE` 策略

这是最容易混淆的一点，务必分清：

| | **IDLE 调度类**（本篇） | **`SCHED_IDLE` 策略** |
|---|---|---|
| 归属文件 | `idle.c`（独立调度类） | `fair.c`（CFS/EEVDF 内部） |
| 优先级 | **最低的类**，低于 fair | **fair 类内部最弱**，低于 `SCHED_NORMAL` |
| 载体 | 每 CPU 的内核空闲任务（PID 0） | 普通用户进程 |
| 作用 | 无事可做时进入低功耗 | 只在"真的没人要 CPU"时才跑的后台任务 |
| 用户可见 | 否（内核内部） | 是（`chrt` / `sched_setscheduler` 可设） |

**一句话**：`SCHED_IDLE` 是"给用户的最弱优先级"，本质还是 fair 类；而 **IDLE 调度类**是"CPU 没活干时的停靠站"。源码里也专门注明二者无关。

> [!WARNING] 别把两者当一回事
> `SCHED_IDLE` 任务仍然走公平调度（权重极低），它**不会**让 CPU 进低功耗状态；让 CPU 进低功耗的是 **IDLE 调度类**的空闲任务。

## 🔁 3. idle 循环：空闲任务在干什么

空闲任务的主体是一个**循环**，核心逻辑可以抽象为：

```
do_idle():
    loop:
        若 need_resched()  → 退出循环，回去调度
        进入低功耗（cpuidle / wfi / hlt ...）
        被中断唤醒
```

要点：

1. **先检查是否需要重新调度**：如果已经有任务在等，直接退出，不睡；
2. **否则尝试进入低功耗状态**：这是省电的关键；
3. **被中断唤醒后重新循环**：醒来第一件事又是检查 `need_resched()`。

### 3.1 两种"睡法"

| 方式 | 行为 | 场景 |
|---|---|---|
| **轮询（polling）** | 开中断空转，什么都不省 | 调试、或已知马上会醒（省下进出低功耗的开销） |
| **深睡（WFI/HLT）** | 执行 CPU 睡眠指令，等中断唤醒 | 正常空闲 |

> [!TIP] 轮询有时反而更优
> 进/出深度睡眠状态本身有开销。如果马上就有活，**空转几微秒**比"睡下再被叫醒"更划算。内核因此保留了强制轮询的开关。

## ⚡ 4. 省电与唤醒

### 4.1 cpuidle 框架与 C-state

CPU 通常有多个**低功耗状态**（C-state / idle state），越深越省电，但**退出延迟越大**。

- **governor（调节器）**负责选一个合适的 C-state；
- 选择依据：**预测的空闲时长** vs **各状态的退出延迟**；
- 目标：在"不拖慢唤醒"的前提下尽量省电。

> [!NOTE] 延迟与功耗的权衡
> 睡得越深越省电，但醒来越慢。如果预测空闲很短却睡得很深，醒来时任务已经等了一会儿 → **延迟变差**。这就是为什么需要 governor 做预测，而不是无脑选最深的。

### 4.2 无滴答（tickless / NOHZ）

传统内核每个 CPU 都有一个**周期性时钟中断（tick）**，即便无事可做也会被周期性唤醒——非常费电。

**NOHZ（tickless）** 的做法：

- 空闲时**停掉周期 tick**；
- 改为**按需**设置下一个定时器；
- 只有真正有定时需求时才唤醒 CPU。

> 于是"空闲"才真正"空闲"：不被无意义的 tick 打扰。

### 4.3 唤醒路径

- 有任务被唤醒 → 向目标 CPU 发**调度 IPI** / 置位"需要重新调度"标志；
- 目标 CPU 从睡眠指令中返回 → 在 idle 循环里检测到 `need_resched()` → 退出空闲 → 正常调度。

> [!WARNING] "睡死"是设计上的大忌
> 如果唤醒标志与睡眠指令之间存在**竞态窗口**（检查完"没人要我"之后、真正睡下之前，来了个任务），CPU 就会睡过头。因此检查与入睡之间必须保证中断不被意外丢失——这是 idle 路径里最微妙的部分。

## ⚖️ 5. 空闲与负载均衡

一个 CPU 进入空闲前，通常不会立刻躺平，而是**先尝试"再抢救一下"**：

- 触发一次**空闲负载均衡（newidle balance）**：看看别的 CPU 是不是压着任务，能不能拉过来；
- 拉到了就继续干活，拉不到才真正进入低功耗。

> 这样避免了"一个 CPU 忙死、一个 CPU 睡死"的浪费。多核下这一点尤其重要。

## 🧭 6. 边界与常见误区

> [!WARNING] 空闲任务里**不能睡眠**
> 空闲任务是最底层的兜底任务——如果它自己都去睡了，CPU 就真的没人管了。所以内核明确规定：**在空闲任务上下文中调用调度（睡眠）是非法操作**，一旦发生会打印错误并告警。

其他易错点：

1. **空闲任务不是"什么都不做"**：它承担了低功耗、tickless、负载均衡、时间记账等一堆职责；
2. **`SCHED_IDLE` 不等于空闲任务**（见 §2）；
3. **IDLE 类不可被"抢占"意义上的抢占**：它只会在有任务时就绪时被替换；
4. **CPU 下线路径复用空闲任务**：CPU 热插拔时，空闲任务会走一条"死亡"分支完成下线收尾。

---

## 🧭 一句话总结

> **IDLE 类 = 每 CPU 一个永远就绪的兜底任务；没活干时它把 CPU 送进低功耗（cpuidle + tickless），有活时被中断唤醒立刻让位。它管的是"省电与唤醒"，不是"调度谁跑"。**
