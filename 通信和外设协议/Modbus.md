# 📡 Modbus 通信协议完整技术手册（RTU / ASCII / TCP）

> [!INFO] 笔记概览
> - **协议定位**：应用层主从问答协议，串行线上跑 RTU/ASCII，以太网上跑 TCP；本篇聚焦**协议帧结构与语义**，RS-485 驱动时序见 [[modbus]]。
> - **内容范围**：主从角色 · 三种承载模式 · ADU/PDU 帧结构 · 四张数据表 · 功能码 · CRC-16/LRC · 异常响应 · 时序要点
> - **推荐路径**：§1 角色 → §2 模式 → §3 帧结构 → §4 数据模型 → §5 功能码 → §6 校验 → §7 异常

## 👥 1. 组成与角色

| 项目 | 值 |
| :--- | :-- |
| 主站数量 | 1（同时只能一个） |
| 从站地址 | 1~247（0=广播） |
| 从站最大数 | 247 |
| 主动上报 | 不支持，只能被查询 |

- **主站 Master（Client）**：一台总线上只有 1 个主站，负责发起所有请求。
- **从站 Slave（Server）**：最多 247 个（地址 1~247），只响应主站请求。
- **广播地址 0**：主站发到地址 0 时，所有从站接收但**不回包**。

> [!NOTE] 无握手应答
> 主从问答：主站发一帧请求 → 从站回一帧应答，时序先后分明（比 CAN 仲裁简单）。从站在应答帧里用**自己的地址 + 功能码**，主站据此判别回的是哪台。

## 🔀 2. 三种承载模式（RTU / ASCII / TCP）

串行线上是 **RTU** 或 **ASCII** 二选一，网络上是 **Modbus TCP**：

| 模式 | 用途 | 字符 | 校验 | 帧间隔 |
| :-- | :-- | :-- | :-- | :-- |
| **RTU** | 最常用、紧凑 | 二进制字节 | CRC-16/MODBUS | ≥ 3.5 字符静默 |
| **ASCII** | 便于人工读、慢 | 十六进制字符 | LRC | ≥ 1 秒（帧间） |
| **TCP** | 以太网 | 二进制 | 无（靠 TCP + MBAP 长度） | TCP 保证 |

> [!TIP] RTU 字符与静默
> RTU 一个字节 = 一个 UART 字符（通常 8 数据位 + 1 停止位、无校验或偶校验）。两帧之间必须静默 ≥ **3.5 个字符时间**；同一帧内字符间隔必须 < **1.5 个字符时间**，否则接收方丢帧——时序细节与临界波特率见 [[modbus]]。

## 📦 3. 帧结构（ADU / PDU）

协议分两层：

- **PDU**（Protocol Data Unit，应用层）：功能码 + 数据。
- **ADU**（Application Data Unit，线上一整帧）：地址 + PDU + 校验（或 TCP 的 MBAP 头）。

### 3.1 RTU 帧（最常用）

| 字段 | 长度 | 说明 |
| :-- | :--: | :-- |
| 从站地址 | 1B | 0x01~0xF7，0=广播 |
| 功能码 | 1B | 见 §5 |
| 数据 | n B | 与功能码相关 |
| CRC | 2B | **CRC-16/MODBUS**，先发低字节后发高字节 |

```text
┌────────┬────────┬──────────┬───────┬───────┐
│  地址   │ 功能码  │  数据 ... │ CRC低 │ CRC高 │
└────────┴────────┴──────────┴───────┴───────┘
```

### 3.2 ASCII 帧

每个字节先转成 2 个 ASCII 十六进制字符发送；帧以 `:`(0x3A) 起始、`CR LF`(0x0D 0x0A) 结束；校验用 **LRC**（1 个 ASCII 字符对）：

```text
: 地址 功能码 数据 ... LRC CR LF
```

### 3.3 Modbus TCP 帧（MBAP 头 + PDU，无地址/CRC）

| 字段 | 长度 | 说明 |
| :-- | :--: | :-- |
| Transaction ID | 2B | 事务序号，可回显 |
| Protocol ID | 2B | 恒为 0 |
| Length | 2B | 后面 Unit ID + PDU 的字节数 |
| Unit ID | 1B | 相当于从站地址 |
| 功能码 + 数据 | n B | 同 PDU |

### 3.4 长度上限

$$
\text{RTU ADU} \le 256\ \text{B} \Rightarrow \text{PDU} \le 253\ \text{B}; \qquad \text{TCP ADU} = \text{MBAP}(7\text{B}) + \text{PDU} \le 260\ \text{B}
$$

## 🗂️ 4. 数据模型（四张表）

Modbus 把数据分成 4 类，每类都有编号区间（PLC 侧习惯 `4xxxx` 写法）：

| 表 | 单位 | 读写 | 协议地址 | 常见编号 |
| :-- | :-- | :-- | :-- | :-- |
| **Coils 线圈** | 位 | 读+写 | 0x0000~0xFFFF | 00001~09999 |
| **Discrete Inputs 离散输入** | 位 | 只读 | 0x0000~0xFFFF | 10001~19999 |
| **Input Registers 输入寄存器** | 16 位 | 只读 | 0x0000~0xFFFF | 30001~39999 |
| **Holding Registers 保持寄存器** | 16 位 | 读+写 | 0x0000~0xFFFF | 40001~49999 |

> [!NOTE] 寄存器字节序与容量
> - 寄存器 **16 位、大端**（RTU 里先发高字节）；
> - 一帧可读写 1~125 个寄存器（≤ 2000 位）。

## 🔢 5. 常用功能码

| 码(HEX) | 名称 | 数据（请求） | 数据（应答） |
| :--: | :-- | :-- | :-- |
| **01** | 读线圈 Read Coils | 起始位(2B)+数量(2B) | 字节数(1B)+位打包数据 |
| **02** | 读离散输入 | 同上 | 同上 |
| **03** | 读保持寄存器 | 起始寄存器(2B)+数量(2B) | 字节数(1B)+寄存器值(2B×n) |
| **04** | 读输入寄存器 | 同上 | 同上 |
| **05** | 写单线圈 | 输出地址(2B)+值(2B, FF00=ON,0000=OFF) | 原样回显 |
| **06** | 写单寄存器 | 寄存器地址(2B)+值(2B) | 原样回显 |
| **0F** | 写多线圈 | 起始位+数量+字节数+数据 | 地址+数量 |
| **10** | 写多寄存器 | 起始寄存器+数量+字节数+数据 | 地址+数量 |

> [!TIP] 协议地址 vs 编号
> PDU 内部寻址从 0 开始（协议地址），对应"编号 − 1"。例如"保持寄存器 40001" = 协议地址 `0x0000`。

### 5.1 读保持寄存器（0x03）示例

主站请求（从站 1，读起始 0x0000 的 2 个寄存器）：

```text
01  03  00 00  00 02  C4 0B
│   │   └地址┘ └数量┘ └CRC─┘
从站 功能 起始寄存器 数量  CRC-16(MODBUS)
```

从站应答（返回 4 字节，寄存器值 0x1234、0xABCD）：

```text
01  03  04  12 34  AB CD  00 20
│   │   │   └──2个寄存器(大端)─┘└CRC┘
地址 功能 字节数(4)
```

## 🛡️ 6. CRC-16/MODBUS 与 LRC

### 6.1 CRC-16 计算规则

| 参数 | 值 |
| :--- | :-: |
| 多项式 Poly | `0x8005`（反映射后 `0xA001`） |
| 初值 Init | `0xFFFF` |
| 输入/输出反转 | true / true |
| 字节序 | **先发低字节后发高字节**（与报文主体相反） |

```c
uint16_t crc = 0xFFFF;
for (each byte in 帧前部)
{
    crc ^= byte;
    for (int i = 0; i < 8; i++)
    {
        crc = (crc & 1) ? (crc >> 1) ^ 0xA001 : (crc >> 1);
    }
}
/* 发送顺序: crc 低字节, crc 高字节 */
```

> [!NOTE] 完整实现与验证用例
> CRC-16 的查表法、位运算法、字节序逆序规则与官方测试向量，见 [[modbus]] §4「CRC-16 校验」。

### 6.2 LRC（ASCII 用）

$$
\text{LRC} = \big(\sim(\text{地址} + \text{功能码} + \text{数据})_{\text{各字节和的低 8 位}} + 1\big)\ \&\ 0xFF
$$

即"求和取低 8 位 → 取补码（取反加一）"，以 1 个 ASCII 字符对发送。

## ⚠️ 7. 异常响应（Exception）

从站不能完成请求时，回一帧异常：**功能码最高位置 1（功能码 + 0x80）** + 1 字节异常码。广播请求从站不回异常（广播本来就不回包）。

| 码 | 含义 |
| :--: | :-- |
| **01** | 非法功能码 |
| **02** | 非法数据地址 |
| **03** | 非法数据值 |
| **04** | 从站设备故障 |
| **05** | 已接收、正在处理（确认） |
| **06** | 从站忙，稍后重试 |
| **08** | 内存奇偶校验错误 |
| **0A** | 网关路径不可用 |
| **0B** | 网关目标无响应 |

> [!EXAMPLE] 异常帧示例
> 读不存在的寄存器时，从站回 `01 83 02` + CRC（功能码 `0x03 → 0x83`，异常码 `02` 非法数据地址）。

## ⏱️ 8. 时序要点单

| 项目 | RTU | ASCII |
| :--- | :-- | :-- |
| 帧间隔 | ≥ 3.5 字符静默 | ≥ 1 s |
| 帧内字符间隔 | < 1.5 字符，否则丢帧 | — |
| 单双向 | 主→从一问一答 | 主→从一问一答 |
| 超时重试 | 主站未收到应答可重试（通常 3 次） | 同左 |

> RTU 一个字节 = 一个 UART 字符，符合 8N1/8E1 等 UART 时序。
