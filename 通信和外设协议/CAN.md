# CAN 通信协议技术总结（普通 CAN 与 CAN-FD）

## 1. 组成与物理特性

- **物理层**：两线差分总线 `CAN_H` 与 `CAN_L`，不发送数据时两线同时被拉到合格电平，抗共模干扰强、适合长距离高噪声环境。
- **显性 / Dominant（逻辑 0）**：`CAN_H` 拉高、`CAN_L` 拉低（差分电压约 2 V）。
- **隐性 / Recessive（逻辑 1）**：`CAN_H`、`CAN_L` 都接近 2.5 V（差分电压约 0 V）。
- **显性优先（线与 / wire-AND）**：当总线上的某个节点发隐性而另一个发显性时，总线表现为显性。这是 CAN 仲裁、应答、错误报告、总线唤醒等机制的物理基础。
- **多主、无地址**：任何节点在总线空闲时都可发起传输；靠报文 ID 参与仲裁，没有 I2C 那样的从机地址。

### 1.1 电平与逻辑汇总

| 名称 | 逻辑 | CAN_H | CAN_L | 差分电压 | 优先级 |
| :-- | :--: | :--: | :--: | :--: | :--: |
| 显性 Dominant | **0** | 约 3.5 V | 约 1.5 V | ≈ 2 V | 高（覆盖隐性） |
| 隐性 Recessive | **1** | 约 2.5 V | 约 2.5 V | ≈ 0 V | 低 |

---

## 2. 位速率与同步

- **经典（普通）CAN**：总线位速率 ≤ 1 Mbit/s，全程单一速率。
- **CAN-FD**：分为两段位速率
  - **仲裁 / 控制段（nominal bit rate）**：与各家协议协商，常见 125 k ~ 1 Mbit/s。
  - **数据段（data bit rate）**：BRS=1 后切换，常见 2 ~ 10 Mbit/s 甚至更高。
- **位时间组成（一个 bit 分为 4 段）**：同步段（SS）、传播段（PS）、相位缓冲段 1（PBS1）、相位缓冲段 2（PBS2）；采样点位于 PBS1 与 PBS2 交界。
- **同步方式**：硬同步发生在帧起始 SOF；重同步发生在隐性→显性跳变沿（总线从隐性跳为显性），用于纠正各节点时钟偏差。

---

## 3. 仲裁机制（CSMA/CD + 多主）

节点发送时**边发边收**，逐位比较：

1. 若节点发送**隐性=1**，却读到总线仍是隐性→继续。
2. 若节点发送**隐性=1**，却读到总线被别的节点拉成**显性=0**→说明自己优先级低，**立即退出仲裁**，转入接收。
3. **ID 数值越小，优先级越高**（显性 0 越多越靠前）。

### 3.1 仲裁示例

```
NodeA(ID=0x100): 发送位  0  1  1  0  ...
NodeB(ID=0x0FF): 发送位  0  0  ...
总线实际         :        0  0  ...   ← 第2位 NodeA发隐性1、NodeB发显性0 → 总线为0
结果             : NodeA 仲裁失败退出，NodeB 赢得总线继续发
```

> 注意：这里"逻辑 0=显性"，与通常"1 表示高"直觉相反，是最容易弄反的点。

---

## 4. 经典（普通）CAN 帧格式

### 4.1 数据帧（标准帧，11 位 ID）

`隐藏起始 → 数据 → 校验 → 应答 → 结束`，字段顺序如下：

| 字段 | 位长 | 说明 |
| :-- | :--: | :-- |
| SOF | 1 | 帧起始，固定显性 0 |
| Identifier | 11 | 仲裁 ID（ID10..ID0，高位在前） |
| RTR | 1 | 0=数据帧；1=远程帧 |
| IDE | 1 | 0=标准帧（11 位 ID）；1=扩展帧 |
| r0 | 1 | 保留位，显性 0 |
| DLC | 4 | 数据长度（0~8） |
| Data | 0~8 字节 | 数据（先 MSB） |
| CRC | 15 | 从 SOF 到数据段末尾计算出的校验 |
| CRC 分隔符 | 1 | 隐性 1 |
| ACK 槽 | 1 | 发送方发隐性；任一接收节点拉显性=ACK |
| ACK 分隔符 | 1 | 隐性 1 |
| EOF | 7 | 帧结束，固定隐性 |
| IFS | 3 | 帧间间隔（总线空闲恢复） |

### 4.2 扩展帧（29 位 ID）

在 11 位 ID 之后插入：

```
ID(11) + SRR(1) + IDE(1, 隐性) + ID 扩展(18) + RTR + r1 + DLC...
```

### 4.3 位填充（Bit Stuffing）

- 从 **SOF 到 CRC 段**（含）之间，每出现 **连续 5 个相同电平**，就**插入 1 个反向位**。
- 目的：保证总线有足够的跳变沿，避免节点长时间采样不到边沿而失同步。
- 接收方在解析时把插入位移除；CRC 分隔符之后不再填充。

---

## 5. 应答（ACK）与错误

- **应答**：发送方在 ACK 槽发隐性；所有正确接收的节点在这一位把总线拉成显性来"确认"。发送方若没有读到显性，则报 ACK 错误。
- **错误类型（6 类）**：位错误、填充错误、CRC 错误、形式（格式）错误、ACK 错误、仲裁失败（只在发送数据时才能发出）。
- **错误帧**：节点检测到错误后，连续发送 **6 个显性位**（错误标志），终止当前帧，所有节点重同步。
- **错误计数**：发送错误计数 TEC 与接收错误计数 REC；进入"错误主动 / 错误被动 / 总线关闭"状态，超过阈值自动退出总线。

---

## 6. CAN-FD（Flexible Data-rate）

在经典 CAN 基础上扩展，兼容仲裁期间的普通速率，数据段提速：

1. **FDF 位**：替代经典帧的 r0；`FDF=1`（隐性）表示这是 CAN-FD 帧。
2. **BRS 位（Baud Rate Switch）**：`BRS=1` 时，从 BRS 之后的数据段切换为数据位速率；`BRS=0` 则全程保持仲裁速率。
3. **ESI 位**：发送方处于错误被动时输出显性。
4. **数据长度扩展**：DLC=9~15 映射到 12 / 16 / 20 / 24 / 32 / 48 / 64 字节（经典最大 8 字节）。
5. **CRC 扩展**：数据长度 ≤ 16 字节用 CRC-17，> 16 字节用 CRC-21；且 **CRC 覆盖仲裁段 + 数据段**（比经典更强，经典 CRC 不覆盖仲裁）。
6. **无远程帧**：CAN-FD 不支持远程帧。
7. **速率切换后的位**：数据段（数据 + CRC + CRC 分隔符在数据速率下发送）之后，回到仲裁速率继续 ACK / EOF。

### 6.1 CAN-FD 位时序示意

```
仲裁/控制段(nominal)        ──BRS=1→  数据段(data rate)      ──回到 nominal──
SOF | ID | FDF | res | BRS | ESI | DLC | Data(0~64B) | CRC | CRC分隔 | ACK | EOF
（此段按仲裁位速率采样）             （此段按数据位速率，位更“窄”更快）
```

### 6.2 高速下的 TDC（发送器延迟补偿）

当数据位速率很高（通常 ≥ 2~3 Mbit/s）时，发送节点自身发送的位经收发器环回有延迟，采样点会偏移。需要调用 **TDC（Transmitter Delay Compensation）** 进行补偿，或在 CAN-FD 控制器中启用二次采样点。

---

## 7. CAN 与 CAN-FD 对比

| 维度 | 普通 CAN（CAN 2.0） | CAN-FD |
| :-- | :-- | :-- |
| 位速率 | 单一，≤ 1 Mbit/s | 仲裁段 + 更高数据段（倍数级提升） |
| 数据长度 | ≤ 8 字节 | ≤ 64 字节 |
| BRS 速率切换 | 不支持 | 支持（数据段加速） |
| CRC | CRC-15，不覆盖仲裁 | CRC-17 / CRC-21，覆盖仲裁+数据 |
| 远程帧 | 支持 | 不支持 |
| TDC | 通常不需要 | 高速时必需 |
| 上层协议 | J1939、CANopen 等 | 同上，扩展报文 |
