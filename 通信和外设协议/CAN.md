# 🚌 CAN 通信协议完整技术手册（经典 CAN 与 CAN-FD）

> [!INFO] 笔记概览
> - **协议定位**：两线差分、多主、无地址、基于报文 ID 仲裁的串行总线，抗共模干扰强，广泛用于汽车与工业现场。
> - **内容范围**：显性/隐性电平 · 位时间与同步 · CSMA/CD 仲裁 · 帧格式与位填充 · ACK 与错误状态机 · CAN-FD 扩展 · DLC 映射
> - **推荐路径**：§1 物理层 → §2 位速率 → §3 仲裁 → §4 帧格式 → §5 错误 → §6 CAN-FD → §7 对比

---

## 🔌 1. 组成与物理特性

两线差分总线 `CAN_H` 与 `CAN_L`，不发送数据时两线被拉到合格电平，抗共模干扰强、适合长距离高噪声环境。  

-------------

### 1.1 显性 / 隐性与"线与"

| 名称 | 逻辑 | CAN_H | CAN_L | 差分电压 | 优先级 |
| :-- | :--: | :--: | :--: | :--: | :--: |
| **显性 Dominant** | **0** | 约 3.5 V | 约 1.5 V | ≈ 2 V | 高（覆盖隐性） |
| **隐性 Recessive** | **1** | 约 2.5 V | 约 2.5 V | ≈ 0 V | 低 |

> [!NOTE] 显性优先（wire-AND，线与）
> 当总线上某节点发隐性、另一节点发显性时，总线表现为**显性**。这是 CAN 仲裁、应答、错误报告、总线唤醒等机制的物理基础。多主、无地址：任何节点在总线空闲时都可发起传输，靠报文 ID 参与仲裁。

## ⏱️ 2. 位速率与同步

| 类型 | 位速率 |
| :--- | :----- |
| **经典 CAN** | 总线位速率 ≤ 1 Mbit/s，全程单一速率 |
| **CAN-FD 仲裁段** | nominal bit rate，常见 125 k ~ 1 Mbit/s |
| **CAN-FD 数据段** | BRS=1 后切换，常见 2 ~ 10 Mbit/s 甚至更高 |

**位时间组成**（一个 bit 分为 4 段）：

```text
┌────┬──────────┬───────────┬───────────┐
│ SS │    PS    │   PBS1    │   PBS2    │
└────┴──────────┴───────────┴───────────┘
 同步   传播段      相位缓冲1     相位缓冲2
                          ▲
                    采样点（PBS1/PBS2 交界）
```

- **SS（同步段）**、**PS（传播段）**、**PBS1（相位缓冲段1）**、**PBS2（相位缓冲段2）**；采样点位于 PBS1 与 PBS2 交界。
- **同步方式**：硬同步发生在帧起始 SOF；重同步发生在**隐性→显性**跳变沿，用于纠正各节点时钟偏差。

## ⚖️ 3. 仲裁机制（CSMA/CD + 多主）

节点发送时**边发边收**，逐位比较：

```text
① 发隐性(1)，读到隐性(1) → 继续发送
② 发隐性(1)，读到显性(0) → 优先级低，立即退出仲裁，转接收
③ ID 数值越小 → 显性 0 越多 → 优先级越高
```

### 3.1 仲裁示例

```text
NodeA(ID=0x100): 发送位  0  1  1  0  ...
NodeB(ID=0x0FF): 发送位  0  0  ...
总线实际        :        0  0  ...   ← 第2位 A发隐性1、B发显性0 → 总线为0
结果           : NodeA 仲裁失败退出，NodeB 赢得总线继续发
```

> [!CAUTION] 最易弄反的点
> 这里"**逻辑 0 = 显性**"，与通常"1 表示高"的直觉相反。ID 越小 = 前导显性 0 越多 = 优先级越高。

## 📦 4. 经典（普通）CAN 帧格式

### 4.1 数据帧（标准帧，11 位 ID）

`帧起始 → 仲裁 → 控制 → 数据 → 校验 → 应答 → 结束`：

| 字段             |   位长   | 说明                    |
| :------------- | :----: | :-------------------- |
| **SOF**        |   1    | 帧起始，固定显性 0            |
| **Identifier** |   11   | 仲裁 ID（ID10..ID0，高位在前） |
| **RTR**        |   1    | 0=数据帧；1=远程帧           |
| **IDE**        |   1    | 0=标准帧（11 位 ID）；1=扩展帧  |
| **r0**         |   1    | 保留位，显性 0              |
| **DLC**        |   4    | 数据长度（0~8）             |
| **Data**       | 0~8 字节 | 数据（先 MSB）             |
| **CRC**        |   15   | 从 SOF 到数据段末尾计算        |
| **CRC 分隔符**    |   1    | 隐性 1                  |
| **ACK 槽**      |   1    | 发送方发隐性；任一接收节点拉显性=ACK  |
| **ACK 分隔符**    |   1    | 隐性 1                  |
| **EOF**        |   7    | 帧结束，固定隐性              |
| **IFS**        |   3    | 帧间间隔（总线空闲恢复）          |

### 4.2 扩展帧（29 位 ID）

在 11 位 ID 之后插入：

```text
ID(11) + SRR(1) + IDE(1,隐性) + ID扩展(18) + RTR + r1 + DLC ...
```

### 4.3 位填充（Bit Stuffing）

> [!NOTE] 位填充规则
> 从 **SOF 到 CRC 段**（含）之间，每出现**连续 5 个相同电平**，就**插入 1 个反向位**。
> - 目的：保证总线有足够跳变沿，避免节点长时间采样不到边沿而失同步；
> - 接收方解析时移除插入位；**CRC 分隔符之后不再填充**。

## 🛡️ 5. 应答（ACK）与错误

- **应答**：发送方在 ACK 槽发隐性；所有正确接收的节点在这一位把总线拉成显性来"确认"。发送方若没读到显性，则报 ACK 错误。
- **错误帧**：节点检测到错误后，连续发送 **6 个显性位**（错误标志），终止当前帧，所有节点重同步。

**6 类错误**：位错误、填充错误、CRC 错误、形式（格式）错误、ACK 错误、仲裁失败（只在发送数据时才能发出）。

**错误状态机**（发送错误计数 TEC / 接收错误计数 REC）：

```text
        TEC/REC < 128          128 ≤ TEC/REC ≤ 255         TEC > 255
错误主动 ────────────► 错误被动 ────────────────► 总线关闭 (Bus-Off)
(Error-Active)          (Error-Passive)            检测到 128 次 11 连续隐性后可恢复
```

## 🚀 6. CAN-FD（Flexible Data-rate）

在经典 CAN 基础上扩展，兼容仲裁期间的普通速率，数据段提速：

| 特性         | 说明                                            |
| :--------- | :-------------------------------------------- |
| **FDF 位**  | 替代经典帧的 r0；`FDF=1`（隐性）表示 CAN-FD 帧              |
| **BRS 位**  | `BRS=1` 从 BRS 之后的数据段切数据位速率；`BRS=0` 全程仲裁速率     |
| **ESI 位**  | 发送方处于错误被动时输出显性                                |
| **数据长度**   | DLC=9~15 映射到 12/16/20/24/32/48/64 字节（经典最大 8）  |
| **CRC 扩展** | ≤16 字节用 CRC-17，>16 字节用 CRC-21；**覆盖仲裁段 + 数据段** |
| **无远程帧**   | CAN-FD 不支持远程帧                                 |

### 6.1 CAN-FD 位时序示意

```text
仲裁/控制段(nominal)      ──BRS=1→  数据段(data rate)   ──回到 nominal──
SOF│ID│FDF│res│BRS│ESI│DLC│ Data(0~64B) │CRC│CRC分隔│ACK│EOF
（此段按仲裁位速率采样）    （此段按数据位速率，位更"窄"更快）

对比can2.0
SOF|ID|RTR|IDE|(ID18 BIT)|R0|DLC|DATA(0~8BIT)|CRC|CRC分隔|ACK|ACK SLOT|EOF|IFS(3BIT)
```

### 6.2 高速下的 TDC（发送器延迟补偿）

> [!WARNING] TDC 必需场景
> 当数据位速率很高（通常 ≥ 2~3 Mbit/s）时，发送节点自身发出的位经收发器环回有延迟，采样点会偏移。需启用 **TDC（Transmitter Delay Compensation）** 补偿，或在 CAN-FD 控制器中配置二次采样点（SSP）简单说就是算出线上延迟再去算出一个新采样点SSP去重新采样。

## 🆚 7. CAN 与 CAN-FD 对比

| 维度 | 普通 CAN（CAN 2.0） | CAN-FD |
| :-- | :-- | :-- |
| 位速率 | 单一，≤ 1 Mbit/s | 仲裁段 + 更高数据段（倍数级提升） |
| 数据长度 | ≤ 8 字节 | ≤ 64 字节 |
| BRS 速率切换 | 不支持 | 支持（数据段加速） |
| CRC | CRC-15，不覆盖仲裁 | CRC-17 / CRC-21，覆盖仲裁+数据 |
| 远程帧 | 支持 | 不支持 |
| TDC | 通常不需要 | 高速时必需 |
| 上层协议 | J1939、CANopen 等 | 同上，扩展报文 |

## ✅ 落地校验清单（Checklist）

> [!SUCCESS] CAN 节点上线前必过
> - [ ] **终端匹配**：总线两端各 120 Ω，中间节点不并联终端电阻
> - [ ] **位速率/采样点**：全网节点 nominal 位速率一致，采样点位置对齐（典型 75%~87.5%）
> - [ ] **仲裁认知**：牢记"逻辑 0=显性、ID 越小优先级越高"
> - [ ] **位填充**：SOF~CRC 段连续 5 位插反位，CRC 分隔符后不填充
> - [ ] **错误状态**：监控 TEC/REC，处理 Bus-Off 恢复策略
> - [ ] **CAN-FD 一致性**：FDF/BRS/ESI 配置匹配，DLC>8 用映射表
> - [ ] **CAN-FD CRC**：≤16B 用 CRC-17，>16B 用 CRC-21
> - [ ] **TDC/SSP**：数据段 ≥2~3 Mbit/s 时启用发送器延迟补偿
> - [ ] **共模范围**：确认收发器共模电压范围适配长线缆/多节点
